Step 1 – 2

可观测性先行，标尺在开始前定好

Transaction Search

logs put-resource-policy（授权 X-Ray 写 aws/spans）→ xray update-trace-segment-destination → 设置索引比例。1% 免费；做评估需要完整 trace 时用 100%，注意成本。

ADOT 自动埋点

AgentCore CLI 部署时自动埋点；CDK + Direct Code Deploy 则在包里带 aws-opentelemetry-distro，entrypoint 用 opentelemetry-instrument agent.py。不改业务代码。

先验证再往下走

发 1 条请求，确认 invoke_agent / execute_tool / chat 三类 span 都落地（本例 13 个）。没开 Transaction Search 不会报错，只是后面全是 0 条。

CDK：agent stack

AgentCore Runtime + endpoint + IAM role；tracingEnabled；固定「今天」等环境变量，让标准答案可复现。

CDK：eval stack

自定义 LLM-as-judge evaluator + Online Evaluation Config（线上流量 100% 自动打分）。它就是 run 之前冻结的标尺。

先查尺子

用 get-evaluator 读真实值域（曾把 [0,1] 误记为 [0,6]）；生产里有没有 safety evaluator；在线评估只覆盖它配置的那个 runtime。

Step 5 · Insights ③

同一批根因，为什么先改 Prompt、再改 Tool

第 1 轮 · p1（Prompt）· FAIL
  • 依据：最大子类「逻辑矛盾 / 资格判断」12 个 session；系统性失败 prod_005 / prod_008 是「超窗口仍暗示可退」—— 工具数据对、模型判断错
  • 改法：v1 后追加两句：只给一个结论、不暗示例外；可退款时写出逐件金额与合计
  • 命中：prod_008 3/4→0/4 · prod_014 3/4→0/4 · prod_005 3→1
  • 副作用：prod_001 0→3 · prod_018 1→3 · prod_010 0→2 —— 全是金额计算；Correctness 失败 23→23
第 2 轮 · t1（Tool）· 通过 S0 / S1
  • 依据（不是 fixType）：出错的是「模型自己做确定性计算」—— 窗口比较、券分摊、折旧费基数、运费；Execution summary 显示 16 个 session 的主流路径正是如此
  • 改法：prompt 不变，打开 AGENT_TOOL_TIER=enhanced，由工具直接返回资格与金额
  • 结果：Correctness 失败 23→13；系统性失败场景全部 0/4
  • 确认：40 道未用于挑选的题，对照 b0，Δ +0.162，95% CI [+0.083, +0.243]；代价 token +56%
insights 定「修什么」 → 多批次普遍性定「真不真」 → 点进 span 定「改哪层」 → 事先登记的门禁定「改没改好」

    → 券在各商品间的分摊明细
# trace：get_order → check_return_eligibility → calculate_refund

说明：新工具和标准答案用的是同一套规则函数（agent/tools.py）。这正是 Tool 层修复的含义 —— 业务规则由代码执行、模型只负责解释；但也意味着它在这类「规则可写成代码」的问题上提升最大，判断与表达类问题仍要靠 Prompt。

CloudWatch Omni · 界面

在 IDE 里看见每一步

Which One

CloudWatch 标准版 vs Omni 版

CloudWatch 标准版
  • 在哪跑：云上，候选是独立 AgentCore runtime
  • 怎么调：AWS CLI —— dataset、batch evaluation、insights、recommendation
  • 评分：托管判官，按 session 注入 ground truth；TOOL_CALL / SESSION 级都能跑
  • 适合：生产团队、CI/CD、交给 coding agent 自动执行
  • 代价：每个候选要部署；批次与评估按调用计费
Omni 版
  • 在哪跑：本地 dev server，候选靠 OMNI_PROMPTS_OVERRIDE 切换
  • 怎么调：Omni MCP 工具；云端 trace 用 search_agent_traces（SQL）
  • 评分：manage_evaluations run；本地 SESSION 级只有 1 个有效观测
  • 适合：IDE 里快速迭代 prompt，部署前先筛选
  • 前提：Kiro 带 AWS_REGION 启动；MCP 握手需要 token

两者共用同一套方法：全层快照 · 多批次基线 · A/A 校准 · 事先登记 · 只改一层 · 分阶段收紧
