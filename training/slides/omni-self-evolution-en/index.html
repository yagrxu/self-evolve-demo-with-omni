Why Omni

Iterate fast locally, keep production evidence

Inner loop is local

Switching a prompt only restarts the dev server; no runtime deploy per candidate. A replay round takes minutes.

Evidence comes from prod

Failing samples are pulled from cloud traces and reproduced locally; production online eval is the ruler frozen before the run.

Coding agents call it

Omni exposes its features as MCP tools; an agent in Kiro / Claude Code follows the skill step by step and stops for human review.

How it is driven

Skill sets the steps, MCP fetches evidence, CLI does the math

Division of labor
  • Skill (omni-self-evolution v2): 11 steps, stop points, invariants, staged gates — tells the agent what to do and what not to do
  • MCP (Omni extension): trace queries, local dev server, test agent, evaluators, datasets
  • CLI / scripts: scripts/omni.mjs calls MCP; se_*.py split, diagnose, bootstrap, gate — numbers come from scripts, not model estimates
  • UI: for observing and explaining; every conclusion lands as JSON in the run directory, auditable
  • Run: bash training/omni/scripts/run_step.sh <n> — one step, then stop

Rules
  • Pure function: lowest 30% of blake2b(scenario_id) → holdout; reruns give the same split — no "re-rolling until the candidate passes"
  • control may be read repeatedly; holdout is not read while designing; verify runs once
  • This run's problem: holdout had only 7 items — a single flip is −0.048, so fixed thresholds were mathematically unreachable
  • Fix: size sets up front by "ratio + minimum count"; if short, wait for traffic or add an independent set — never lower the bar

Three Prompt-layer candidates

c2 · No exceptions

Appended rule, 42 → 89 chars: past the return window, offer only exchange or warranty; never hint at an exception.

c3 · Restructure

Full rewrite, 42 → 126 chars: verdict first, then basis, amounts or alternatives. A control that covers both failure types.

What we learned

Fixing one layer often exposes the next

Cross-layer side effect

c1's "state the amounts" surfaced the model's own arithmetic errors (coupon split, depreciation) to users — the 38% Tool-layer share was still there.

Next round: Tool

Same method, CloudWatch version: AGENT_TOOL_TIER=enhanced adds 3 deterministic tools; 40-item confirm set Δ +0.162, CI [+0.083, +0.243].

The skill evolves too

This run left 18 skill revisions: full snapshot, A/A, pre-registration, staged gates, four data groups, measurement vs. calibration logged apart.

One fixed case ≠ better overall ≠ ready to ship: diagnosis answers "where", replay answers "fixed?", gates answer "ship?" — each with its own evidence.

Takeaways

Measure right,
then improve

Versions on spans · full-layer snapshot · check prod evals first · split as a pure function · repeated runs + A/A
Gates pre-registered and tightened by stage · one layer per round · write back locally, roll back anytime
