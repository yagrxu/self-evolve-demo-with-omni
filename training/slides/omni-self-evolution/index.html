Why Omni

本地快速迭代，云端保留生产证据

内环在本地

换 prompt 只需重启 dev server，不用为每个候选部署一个 runtime。分钟级出一轮 replay。

证据来自生产

失败样本从云上 trace 拉回本地复现；生产在线评估就是 run 之前冻结的标尺。

coding agent 直接调用

Omni 的能力以 MCP 工具暴露，Kiro / Claude Code 里的 agent 按 skill 一步步执行、每步停下给人确认。

How it is driven

Skill 定步骤，MCP 取证据，CLI 做算术

三层分工
  • Skill（omni-self-evolution v2）：11 个步骤、停点、不变量、分阶段门禁 —— 告诉 agent「做什么、不能做什么」
  • MCP（Omni 扩展）：trace 查询、本地 dev server、test agent、evaluator、dataset
  • CLI / 脚本：scripts/omni.mjs 调 MCP；se_*.py 做切分、诊断、bootstrap、门禁 —— 数字由脚本算，不由模型估
  • 界面：用来观察和讲解；结论全部落在 run 目录的 JSON 里，可审计
  • 执行：bash training/omni/scripts/run_step.sh <n>，一次一步、跑完即停

Step 7 · 只改一层

Prompt 层的三个候选

c1 · 补全具体金额

追加约束，42 → 95 字：可以退款时写出每件可退金额、原始运费是否退还及金额、退款合计（元）。

c2 · 禁止承诺例外

追加约束，42 → 89 字：超出退货窗口时只提供换新或保修路径，不暗示例外。

c3 · 重构回答结构

整段重写，42 → 126 字：先给结论，再给依据、金额或替代路径。作为覆盖两类问题的对照。

不变量（脚本断言，不靠自觉） omni_steps.py candidate
  • 每个候选是完整独立的 prompts.json；与基线除 prompt 外逐键一致，model / tool / policy / workflow / 数据的指纹与快照相同
  • prompt 里不得出现订单号、标准答案、工具名或调用顺序 —— 防止对着题目写答案、防止越层

What we learned

修好一层，常会暴露下一层

跨层副作用

c1 要求「写出金额」，把模型心算券分摊、折旧费的错误直接暴露给用户 —— 诊断里 38% 的 Tool 层问题还在。

下一轮改 Tool

同样的方法在 CloudWatch 版上验证：AGENT_TOOL_TIER=enhanced 加 3 个确定性工具，确认集 40 题 Δ +0.162，CI [+0.083, +0.243]。

skill 也在演进

这次运行留下 18 条 skill 修订：全层快照、A/A、事先登记、分阶段门禁、四组数据、测量与校准分开记录。

单条修好 ≠ 全局更好 ≠ 可以发布：诊断回答「改哪里」，replay 回答「修好没有」，门禁回答「能不能发」，各用各的证据。

Takeaways

先测准，
再改进

span 带版本 · 全层快照 · 生产评估先体检 · 切分是纯函数 · 重复采样 + A/A
